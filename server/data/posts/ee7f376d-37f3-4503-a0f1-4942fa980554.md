# GraphRAG代码复现

## 复现流程

### 1.创建虚拟环境

```
conda create -n graphrag python=3.12.4
conda activate graphrag
```

### 2.拉取源码

```
git clone https://github.com/microsoft/graphrag.git
cd graphrag
```

！！！注意

*若直接下载压缩包解压，解压完后需创建一个仓库，不然后续会报错*

*创建仓库方法：*

```
git init
git add .
git commit -m "Initial commit"
```

### 3.安装依赖

```
pip install -e .
```

### 4.创建输入文件夹

```
mkdir -p ./graphrag_ollama/input
```

用于存放待处理的文档/知识库（Windows可以直接手动创建），名字任意，但必须有个`input`子文件夹

将**数据集**放入input目录即可

### 5.初始化项目

```
python -m graphrag init --root ./graphrag_ollama
```

该命令会在`./graphrag_ollama`文件夹下生成`.env`和`setting.yaml`配置文件

### 6.修改`setting.yaml`文件核心配置

使用ollama部署本地语言模型和嵌入模型。（ollama安装和部署没什么大坑，注意更改一下模型保存的路径）

**语言模型不能使用deepseek！！！** 

**DeepSeek R1 是 "推理模型" (Reasoning Model)**

1. **输出格式冲突**：DeepSeek R1 (以及所有 R1 系列) 的特点是在输出最终答案前，会先输出一段 `<think>...</think>` 的思维链内容。
2. **GraphRAG 的机制**：GraphRAG 的 `extract_graph` 步骤极其严格，它要求 LLM 返回 **纯净的 JSON 格式**（用于提取实体和关系）。
3. **崩溃过程**：

- GraphRAG 发送提示词：“请提取实体和关系并以 JSON 格式返回”。
- DeepSeek R1 回复：“`<think>好的，我要开始分析文本了...</think>``json [...]`”。
- GraphRAG 的 JSON 解析器检测到开头不是 `{` 或 `[`，而是 `<think>`，**解析失败**。
- GraphRAG 捕获了该错误（但在非 Debug 模式下有时不打印详细堆栈），认为这段文本提取不出任何实体，于是跳过。
- 因为只有一个 Text Unit，跳过之后任务就结束了，显示 `Pipeline complete`，但知识图谱是空的。

### 7.构建知识图谱

```
python -m graphrag index --root ./graphrag_ollama
```

（构建知识图谱会花费一段时间）

### 8.知识图谱查询

| 方法      | 命令示例                                                     | 用途           |
| --------- | ------------------------------------------------------------ | -------------- |
| 全局查询  | `python -m graphrag query --method global --query  "知识图谱定义"` | 跨文档综合分析 |
| 局部查询  | `python -m graphrag query --method local --query "知识图谱定义"` | 单文档精准检索 |
| DRIFT查询 | `python -m graphrag query --method drift --query "知识图谱定义"` | 动态漂移分析   |
| 基础查询  | `python -m graphrag query --method basic --query "知识图谱定义"` | 传统RAG检索    |
